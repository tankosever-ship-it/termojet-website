# SSR-lite — чек і ґрунтовне тестування

**Дата:** 05.08.2026
**Задача:** за фідбеком SEO-команди — без JavaScript рендерилась мала частина контенту. Максимально перевести на server-side.
**Статус:** реалізовано (SSR-lite), задеплоєно на прод, протестовано.

---

## Що зроблено

**SSR-lite:** сервер кладе повноцінний семантичний HTML кожної сторінки в `<div id="seo-content">` — його бачать усі краулери в сирому HTML (не-JS боти, перша хвиля Google, AI/LLM-боти). React рендериться в `#root`; щойно він заповнюється — CSS ховає `#seo-content`, а `main.jsx` його прибирає. Без дублів, білих екранів, блимку.

Чому не «повний SSR» (renderToString): SPA на Vite з 3D-в'ю`верами/framer-motion — гідрація ризикована й дорога; критичні дані вже в JSON-LD. SSR-lite дає той самий ефект для індексації за малу частку зусиль і ризику.

### Контент у raw HTML по типах сторінок
| Тип | Вміст `#seo-content` | Обсяг |
|---|---|---|
| **Товар** | breadcrumb, H1, фото+alt, ціна ₴, наявність, повний опис, таблиця характеристик, схожі товари, nav | ~4400 симв |
| **Категорія** | breadcrumb, H1, опис, сітка ВСІХ товарів (назва+ціна+лінк), nav | 2800–3700 симв, 35–55 лінків |
| **Стаття блогу** | H1 + повний текст статті + nav | ~1350 симв |
| **Статична** | H1 + опис + nav | ~250 симв |

Коміти: `c82b7dc` (Фаза 1 — товари), `c6c9b63` (Фаза 2 — категорії/статика/блог).

## Тестування

**Обсяг:** 51 URL у RAW HTML + 13 у rendered-DOM; усі типи сторінок + 5 мов (uk/en/pl/fr/de).

### RAW HTML (не-JS краулер) — 51/51 ✅
- [x] `#seo-content` присутній і змістовний на всіх (товар ~4400, категорія 2800–3700, блог ~1350, статика ~250 симв)
- [x] **Єдиний `<h1>`** на кожній сторінці (без дублю) — усі 51
- [x] HTML цілий — опис товару не ламає розмітку (`<script module>` на місці всюди)
- [x] Ціни в грн = очікувана конвертація EUR→₴ (курс НБУ ×1.022) — звірено 15 товарів
- [x] Кількість товарів у сітці категорії = дані API — усі 15 категорій
- [x] Внутрішні посилання (breadcrumb / сітка / nav) присутні
- [x] Head-сигнали (Product JSON-LD, canonical, title) збережено — без регресу

### Rendered-DOM (Googlebot після JS) — ✅
- [x] `#seo-content` прибрано після монтування React — усі
- [x] Єдиний H1 у живому DOM
- [x] Немає білого екрана (root 2000–26000 симв)
- [x] Немає JS-помилок (окрім очікуваного 404 на старому WP-URL — див. нижче)
- [x] Мовні сторінки pl/fr/de — без регресу
- [x] 404 (старі WP-URL) + /cart — працюють як задумано

### Крайні випадки
- Товари без ціни: 0 (усі проставлені) — рядок ціни просто не рендериться, схема без `Offer`
- EN-версії товару/категорії — `#seo-content` коректний
- Категорії з великою кількістю товарів (nasosy — 55 лінків) — усі в raw HTML

### Примітка щодо єдиного «❌» в rendered-тесті
`/pl/product/ksh22g125-200-pl/` — це старий WordPress-URL, який навмисно повертає **HTTP 404** (фікс білих екранів для legacy-посилань). Браузер логує цей 404 як «console error» — це очікувано, не дефект. Сторінка 404 рендериться нормально (не білий екран).

## Вердикт
Задача пройшла тестування повністю. SSR-lite працює на всіх типах сторінок і всіх мовах; критичні SEO-сигнали збережено; білих екранів / дублів H1 / помилок немає.

**Для SEO-команди:** тепер краулери без JS, перша хвиля Google та AI-боти бачать повний контент, ціни й усі внутрішні посилання в сирому HTML. Рекомендація перевірки: GSC → Перевірка URL → «Переглянути HTML» (raw), або відкрити сторінку з вимкненим JS.
