# Soft-404 — фікс

**Дата:** 06.08.2026
**Задача:** під час SEO-тестування нових сторінок виявлено, що неіснуючі URL віддають HTTP 200 замість 404 («м'які 404»).
**Статус:** виправлено, задеплоєно на прод, перевірено. Коміт `290581a`.

---

## Проблема

Catch-all у `backend/server.js` працював як **чорний список**: лише відомі старі WordPress-патерни (`/product/…`, `/product-category/…`, `/ru/…` тощо) віддавали HTTP 404, а **вся решта — 200 + порожня SPA-заглушка**.

Наслідок — будь-який неіснуючий URL віддавав 200 і Google індексував порожні сторінки як **soft-404**:
- `/nonexistent-xyz-123` → 200
- `/catalog/фейкова-категорія` → 200 (хендлер категорії робив `next()`, бо в `CATEGORY_META` немає)
- `/catalog/termojet-mega/фейковий-товар` → 200 (хендлер товару робив `next()`, бо в БД немає)
- `/blog/фейкова-стаття` → 200
- `/pl/catalog/фейк`, глибокі випадкові шляхи → 200

## Рішення

Інвертовано на **білий список** — функція `isKnownRoute(p)` (мовний префікс уже стрипнуто):

1. `KNOWN_ROUTES` — Set валідних статичних роутів (`/`, `/catalog`, `/blog`, `/faq`, `/about`, `/service`, `/delivery`, `/oem`, `/partners`, `/returns`, `/navchannya`, `/portfolio`, `/contacts`, `/files`, `/reviews`, `/privacy`, `/terms`, `/cart`, `/dealers`, `/support`, `/training`, `/warranty`).
2. `/admin` та `/admin/*` — панель.
3. `/catalog/:cat` — валідна лише якщо `CATEGORY_META[cat]` існує.
4. `/catalog/:cat/:slug` — валідний лише якщо товар зі `slug` є в БД (`is_visible = 1`).
5. `/blog/:slug` — валідний лише якщо стаття зі `slug` є в БД (`published = 1`).

Перед перевіркою стрипається мовний префікс `/en /pl /fr /de`. **Fail-open**: на помилці БД повертаємо `true` (краще показати сторінку, ніж хибно 404-ити реальний товар).

Логіка статусу:
```
statusCode = (старий WP-URL АБО НЕ isKnownRoute(шлях)) ? 404 : 200
```

Старі WordPress-URL так само лишаються 404 (окремий патерн `DEAD_WP`).

## Вердикт
Google тепер отримує чесний HTTP 404 на всі неіснуючі URL замість «м'яких 404» з порожньою заглушкою. Валідні сторінки не зачеплено.

---

## ⚠️ Окрема відкрита проблема (НЕ входила в цю задачу)
PL / FR / DE сторінки **не мають серверного SEO взагалі**: `#seo-content` порожній, canonical усіх pl/fr/de = головна (`https://termojet.com.ua/` — сигнал Google «дублікат головної»), title/description generic, hreflang відсутній. Серверна логіка (SSR-lite, injectMeta) написана лише для uk + en. При цьому Merchant-фіди pl/fr/de існують → це реальні цільові ринки. Розширення SSR-lite + canonical/hreflang на pl/fr/de — окрема задача, на погодження.
